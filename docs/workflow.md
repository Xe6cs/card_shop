# سير العمل والحماية

## الفروع

| الفرع | معناه | من يرفع إليه |
|---|---|---|
| `main` | **النسخة الرسمية.** بعد ربط Netlify سيكون هو الموقع المنشور | لا يُرفع إليه إلا بموافقة صاحب المشروع |
| `develop` | فرع التطوير، وكل العمل يتم عليه. سيكون له رابط معاينة على Netlify | Claude تلقائياً بعد كل تعديل |

**مسار أي تعديل:**
1. يُنفَّذ التعديل على `develop`.
2. يُرفع تلقائياً إلى GitHub.
3. تراجعه على رابط المعاينة.
4. توافق.
5. يُنقل إلى `main`.

## الحمايات المفعّلة

| الحماية | ماذا تفعل | أين تعمل |
|---|---|---|
| `.gitignore` | ملفات المفاتيح مثل `.env` و`.env.local` و`*.pem` لا تُضاف أصلاً | جهازك |
| فحص الأسرار قبل الحفظ (`.githooks/pre-commit`) | يرفض حفظ أي ملف فيه مفتاح سري | جهازك |
| فحص قبل الرفع (`.githooks/pre-push`) | يمنع الرفع إلى `main` دون موافقة، ويمنع حذف وسوم النسخ الاحتياطية | جهازك |
| فحص الأسرار على GitHub (`.github/workflows/secret-scan.yml`) | يعيد الفحص على خوادم GitHub عند كل رفع | GitHub |
| الرفع التلقائي | يرفع فرع التطوير فقط، ولا يرفع `main` أبداً | إعدادات Claude المحلية |

## إذا نُقل المشروع إلى جهاز آخر

نفّذ هذا الأمر مرة واحدة داخل المجلد لتفعيل الفحوص المحلية:

```bash
git config core.hooksPath .githooks
```

## إذا أوقف فحص الأسرار عملية حفظ

1. احذف المفتاح من الملف المذكور في الرسالة.
2. ضع المفتاح في `.env.local`، وهو لا يُرفع، أو في إعدادات Netlify.
3. إذا كان المفتاح قد وصل إلى GitHub من قبل فاعتبره مكشوفاً، وأنشئ مفتاحاً جديداً من لوحة الخدمة.

## قاعدة ذهبية

**لا ترسل أي مفتاح سري في المحادثة.** المفاتيح تُوضع في `.env.local` على جهازك أو في لوحة Netlify فقط. ملف `.env.example` يشرح أي المفاتيح عام وأيها سري.
