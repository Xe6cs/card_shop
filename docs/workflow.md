# سير العمل والحماية

## الفروع

| الفرع | معناه | من يرفع إليه |
|---|---|---|
| `main` | **النسخة الرسمية.** بعد ربط Netlify سيكون هو الموقع المنشور | لا يُرفع إليه إلا بموافقة صاحب المشروع |
| `develop` | فرع التطوير، وكل العمل يتم عليه. سيكون له رابط معاينة على Netlify | Claude تلقائياً بعد كل تعديل |

**مسار أي تعديل:**
1. يُنفَّذ التعديل على `develop`.
2. يُرفع تلقائياً إلى GitHub.
3. تراجعه على رابط المعاينة.
4. توافق.
5. يُنقل إلى `main`.

## الحمايات المفعّلة

| الحماية | ماذا تفعل | أين تعمل |
|---|---|---|
| `.gitignore` | ملفات المفاتيح مثل `.env` و`.env.local` و`*.pem` لا تُضاف أصلاً | جهازك |
| فحص الأسرار قبل الحفظ (`.githooks/pre-commit`) | يرفض حفظ أي ملف فيه مفتاح سري. يذكر الملف والسطر ونوع المشكلة فقط، ولا يطبع أي جزء من قيمة المفتاح | جهازك |
| فحص قبل الرفع (`.githooks/pre-push`) | يمنع الرفع إلى `main` دون موافقة، ويمنع حذف وسوم النسخ الاحتياطية | جهازك |
| فحص الأسرار على GitHub (`.github/workflows/secret-scan.yml`) | يعيد الفحص على خوادم GitHub عند كل رفع | GitHub |
| الرفع التلقائي | يرفع فرع التطوير فقط، ولا يرفع `main` أبداً | إعدادات Claude المحلية |

## أين يعمل الموقع الآن؟ (فحص 2026-10-10)

| الموقع | أين يعمل | علاقته بهذا المستودع |
|---|---|---|
| card-shop.net (الرسمي) | WordPress وWooCommerce على خادم OVH في فرنسا | **لا علاقة.** لا يُنشر من GitHub، ولا يتأثر بأي تعديل هنا |
| النسخة الجديدة (هذا المستودع) | غير منشورة بعد | GitHub Pages غير مفعّل، ولا يوجد ربط مع Netlify |

لذلك تغيير خصوصية المستودع أو أي تطوير هنا لا يمكن أن يعطّل الموقع الرسمي.

## بيئة المعاينة

| | الرسمي (`main`) | المعاينة (`develop`) |
|---|---|---|
| الرابط | `<اسم-الموقع>.netlify.app`، ثم card-shop.net بعد الإطلاق فقط | `develop--<اسم-الموقع>.netlify.app` منفصل تماماً |
| محركات البحث | ممنوعة حتى يوم الإطلاق (`CS_ALLOW_INDEXING`) | ممنوعة دائماً |
| قاعدة البيانات والمفاتيح | مشروع الإنتاج | مشروع تطوير منفصل |
| هل تستطيع النشر على الرسمي؟ | — | **لا** |

**كيف يُضمن ذلك:**
1. **الفروع:** يُضبط Netlify لينشر رسمياً من `main` فقط، ورفع `main` ممنوع دون موافقة (`.githooks/pre-push`).
2. **الدومين:** card-shop.net يبقى على خادمه الحالي. لا يتغير إلا بتعديل إعدادات الدومين عند مسجّله، وهذا بيد صاحب المشروع فقط ويوم الإطلاق.
3. **منع الفهرسة:** حارس النشر (`tools/deploy-guard.js`) يعمل في كل بناء على Netlify. يضيف ترويسة `X-Robots-Tag: noindex` ويغلق `robots.txt` لكل نسخة، إلا الرسمية بعد الإطلاق. السماح بالفهرسة يحتاج تعديل `netlify.toml` على `main`، أي بموافقتك.
4. **فصل البيانات والمفاتيح:**
   - في لوحة Netlify تُعطى مفاتيح الإنتاج السرية لسياق **Production** فقط، وللمعاينة قيم من مشروع تطوير منفصل.
   - كخط حماية ثانٍ، يُفشل حارس النشر بناء المعاينة إذا وجد فيه معرّف أي مورد إنتاج (`CS_PROD_FINGERPRINTS`)، حتى لو كان مخفياً داخل مفتاح.
   - يذكر الحارس أسماء المتغيرات فقط، ولا يطبع أي قيمة.

**إعدادات تُضبط في لوحة Netlify عند الربط (المرحلة 1، بإرشادي):**
- Build & deploy ← Branches: **Production branch = `main`**، و**Branch deploys = `develop` فقط**.
- لا يُضاف الدومين `card-shop.net` إلى Netlify.
- متغيرات البيئة: كل مفتاح سري يُحدَّد سياقه، فالإنتاج لـ Production فقط.

> **عند نقل الموقع إلى Next.js (المرحلة 1):** يُنقل منع الفهرسة إلى إعدادات Next.js نفسها، ويُختبر على رابط المعاينة قبل أي خطوة أخرى.

## إذا نُقل المشروع إلى جهاز آخر

نفّذ هذا الأمر مرة واحدة داخل المجلد لتفعيل الفحوص المحلية:

```bash
git config core.hooksPath .githooks
```

## إذا أوقف فحص الأسرار عملية حفظ

1. احذف المفتاح من الملف المذكور في الرسالة.
2. ضع المفتاح في `.env.local`، وهو لا يُرفع، أو في إعدادات Netlify.
3. إذا كان المفتاح قد وصل إلى GitHub من قبل فاعتبره مكشوفاً، وأنشئ مفتاحاً جديداً من لوحة الخدمة.

## قاعدة ذهبية

**لا ترسل أي مفتاح سري في المحادثة.** المفاتيح تُوضع في `.env.local` على جهازك أو في لوحة Netlify فقط. ملف `.env.example` يشرح أي المفاتيح عام وأيها سري.
